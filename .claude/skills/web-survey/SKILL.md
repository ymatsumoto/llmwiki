# 先行研究の網羅探索 (Web Survey)

Web上から関連研究を探索し、**Wikiの現状と照らしてギャップを見つけ**、次に読むべき文献を提示する。取り込み（ingest）はしない — あくまで探索と候補出し。

## 手順

1. **対象を確定**: `$ARGUMENTS` のトピック、または関連する problem / topic ページを確認し、調べる範囲・キーワード（英語の専門用語、想定される手法名、主要著者）を洗い出す。

2. **Wikiの現状を把握**: `wiki/index.md` と関連ページを読み、**既に知っていること / 既に持っているソース**を一覧化する。重複取り込みを避けるため。

3. **多角的に探索**（WebSearch を複数角度で）:
   - キーワード検索（用語・課題の言い換えを変えて複数回）
   - サーベイ/総説論文（"survey" / "review"）を起点に系譜を辿る
   - 主要論文の被引用・引用先（"cited by" / 参考文献）
   - 主要著者・研究グループの最近の仕事
   - 必要に応じ WebFetch で abstract / 論文ページを精読

4. **照合とギャップ分析**: 見つけた研究を3群に分類:
   - **既知**（Wikiに既にある）
   - **未取り込みだが重要**（取り込み候補）
   - **隣接・要検討**
   そのうえで「Wikiに欠けている視点・系譜・反証」を**ギャップ**として言語化する。

5. **取り込み候補リストを提示**:
   | タイトル | 著者(年) | なぜ重要 | URL/DOI | 優先度 |
   |---------|---------|---------|---------|--------|
   - 各候補に想定 `citekey` を付ける。
   - 人間に「どれを `raw/` に入れて `/ingest` するか」を選ばせる（rawは人間がキュレートする層）。

6. **filing（任意）**: 探索で得た領域構造の理解が価値あるものなら、`wiki/topics/<slug>.md` を作成/更新して残すことを提案。発見した課題は `wiki/problems/` に stub 化。新規ページの frontmatter は `CLAUDE.md` §3.0 に従う（`type`/`title`/`description`/`generated`/`root: research` 必須）。

7. **wiki/log.md に追記**（OKF §9, 新しい順）:
   ```markdown
   ## YYYY-MM-DD
   * **Web-survey**: <トピック> — Queries: 使った検索語。Found: 重要候補 N 件（citekey候補 ...）。Gaps: Wikiに欠けていた点。Filed: [topic](topics/....md) / problem stub など（あれば）。
   ```

## 注意
- 出典の確かさを重視。一次情報（論文・公式）を優先し、二次情報には注意書きを付ける。
- 取得した本文・abstract を `raw/` に保存するかは**人間に確認**してから（自動でrawを増やさない）。

## Args
`$ARGUMENTS` — 調査トピック or problem/topic ページ参照。空なら何を調べるか尋ねる。
